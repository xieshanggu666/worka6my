# 📡 舆舟 · 全网舆情监测与危机管理平台

基于 **Vue 3 + Vite + Pinia（前端）+ Express + SQLite（后端）** 的舆情监测与危机处置演示平台。所有数据为 mock，模拟舆情采集与处置闭环。

## 技术栈

- 前端：Vue 3 + Vite + Pinia
- 后端：Node 内置 `node:sqlite` + Express，REST API
- 数据库：`server/pubmon.db`（SQLite，首次启动自动建表 + 预置示例舆情）

## 运行

```bash
npm install
npm run dev
```

前端 http://localhost:5200（Vite 已代理 `/api` 到 http://localhost:4130）。需 Node ≥ 22.13。

## 功能

- **舆情总览**：总量/正面/中性/负面/热点/负面占比统计、情感分布环形图、7 时段热度趋势、渠道来源分布、高频热词云、生效预警规则、危机速览
- **舆情列表**：按情感/渠道/关键词筛选，录入新舆情自动进行情感分析，负面舆情触发预警提示；支持可恢复批量导入（任务化、断点续跑、失败重试、进度与逐条结果回写）
- **预警中心**：预警规则配置（级别/关键词/情感/热度下限/归并话题/时间窗口），规则启停、触发记录与关联舆情、单条/批量解除预警
- **危机处置**：事件建档（话题+方案+研判+邮箱）、状态流转（监测→处置→结案）、统一事件时间线（触发/解除/处置混排）、动作记录、事件回溯（按规则拆分统计）、结案总结与**结案回滚**

## 预警 → 危机闭环

- **多规则并发触发**：一条舆情可同时命中多条规则。同话题下只由级别最高的红/橙规则建一个事件，其余命中规则（含黄色规则）在各自时间窗口内全部并入该事件承接（多对多）；并入规则级别更高时事件自动升级
- **话题 + 时间窗口归并**：每条规则可配置「归并话题」（留空则取命中舆情自身话题）与「时间窗口」（分钟，0=不限）。命中同话题且在窗口内的未结案事件则并入，否则自动建档；同规则不同话题/超窗分别建档
- **时间窗口变更**：`PATCH /api/alerts/:id` 可随时修改归并话题/时间窗口（及级别/关键词等），改动即时作用于后续触发判定，历史触发记录与时间线原样保留
- **重复解除（幂等）**：单条/批量解除对已解除记录幂等，不重复写时间线；解除时间线以 `ref` 关联触发记录，支持「撤销解除」（预警重新生效，原时间线标记失效并留痕）。随结案级联解除的记录不可单独撤销，须回滚结案
- **结案与回滚**：预警解除 → 危机时间线同步（标注来源规则）；危机结案 → 级联解除全部未解除预警（标记 `close` 来源）。`POST /api/crisis/:id/reopen` 回滚结案：恢复结案前状态、仅重开随结案解除的预警、失效对应结案/解除时间线行（保留历史）并追加回滚记录，支持反复结案/回滚
- **统一时间线与统计**：`GET /api/crisis/:id/feed` 合并处置时间线与预警触发/解除记录，按毫秒时间戳混排（支持 `?voided=1` 查看已撤销记录）；未解除计数全链路统一取 `alert_events.status`；总览 `/api/state` 返回 `overview` 统一统计块（生效规则/未解除/累计解除/结案级联解除/事件状态分布/多规则承接事件数）
- **回溯结案**：危机事件支持回溯（按规则拆分的触发统计、关联舆情、完整时间线），结案时写入回溯总结完成闭环

## 批量导入（可恢复任务）

- `POST /api/imports`：`{ idem_key?, items: [{ title, content, source_id, topic, media, idem_key? }] }`，单任务上限 **5000 条**；返回 `202 + jobId`，任务异步分块执行（每块 25 条独立事务，块间让出事件循环）
- **双层幂等**：
  - 任务键 `idem_key`：同一批数据重复提交（网络抖动/双击/刷新）直接返回原任务，不重复执行
  - 条目键（`posts.idem_key` 唯一索引）：自动为 `任务键:序号`；也支持条目自带 `idem_key` 做跨批次内容去重。重试/续跑/重复提交命中已有舆情时跳过，**绝不重复触发预警、重复建档/归并危机**
- **失败重试**：单条失败用 `SAVEPOINT` 只回滚该条，自动重试至多 3 次；仍失败标记 `failed`，任务以 `failed`（部分失败）结束，可一键重试失败条目续跑；瞬时故障不影响同块其他条目
- **进度记录**：任务与逐条状态（pending/success/failed/duplicate、attempts、结果 JSON、错误）实时落库；`GET /api/imports/:id` 回写进度、预警/危机汇总与逐条结果；支持暂停 / 续跑
- **崩溃恢复**：服务重启时把 running/pending 任务转为「已暂停」并保留已提交块的进度，一键续跑断点恢复（不丢、不重）
- **闭环衔接**：每条仍走统一管线（情感分析 → 落库 → 预警触发 → 红/橙级危机自动建档或同话题窗口归并），分块提交让大批量导入时预警/危机边导入边闭环
- 其他接口：`GET /api/imports`（最近任务）、`POST /api/imports/:id/pause`、`POST /api/imports/:id/resume`（兼作失败重试）
- 演练用请求头：`x-sim-fail: 2,5`（指定条目首轮瞬时失败，验证自动重试）、`x-sim-fail-always: 5`（持续失败，验证 failed → 手动重试）、续跑时带 `x-clear-injection: 1`
- `POST /api/posts/batch`（旧接口，≤200 条）保持同步语义，内部改为创建任务并等待结束，响应结构不变（部分失败返回 207）；`POST /api/posts` 单条录入支持可选 `idem_key`，响应结构不变

## 数据库表

`sources` `posts`（含 `idem_key` 幂等键） `hot_words` `alerts` `alert_events`（含 `resolve_source` 解除来源、`event_at_ms` 触发毫秒时间戳） `crisis`（含 `topic/last_trigger_at/closed_at/prev_status`） `crisis_alerts` `crisis_timeline`（含 `kind/ref_type/ref_id/voided` 支持精确撤销与结案回滚留痕） `import_jobs` `import_job_items`（可恢复导入任务与逐条记录）

> 旧库自动迁移：新增 `alerts.merge_topic/merge_window`、`crisis.topic/last_trigger_at/closed_at/prev_status` 列，并把旧的 `crisis.alert_id` 单规则关联迁移到多对多表 `crisis_alerts`（回填话题与最近触发时间）；新增 `posts.idem_key` 列与索引，并自动重建早期版本的 `import_job_items.idem_key` 唯一约束为普通索引（支持跨任务同名幂等键）。
>
> 解除/结案链路升级迁移（幂等可重复执行）：为 `alert_events` 补 `resolve_source`（历史已结案事件下的解除记录回填为 `close`，使其可随结案回滚重开）与 `event_at_ms`（由时间字符串解析回填）；为 `crisis_timeline` 补 `kind/ref_type/ref_id/voided`（按历史 action 文本回填 kind）；为已结案事件回填 `closed_at`。历史时间线行一律保留不删除。
